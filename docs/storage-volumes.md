# Storage volumes

Obsidia's block layer registers physical devices independently of filesystems.
The partition layer validates MBR or GPT metadata and exposes each bounded
partition as a child block device whose I/O is translated and range checked.
Filesystems mount child volumes; they do not parse partition tables.

The development disk is generated by `tools/mkstate_disk.py`. It has primary
and backup GPT metadata and one partition with Obsidia's state-volume type GUID.
The statefs filesystem owns that partition. Older unpartitioned development
images remain readable through a deliberately quarantined whole-disk fallback,
used only when no partition table is present. A malformed table, or a valid
partitioned disk without an Obsidia state volume, is never formatted as a raw
state disk.

Current limits are explicit: 512-byte logical sectors, 128 inspected GPT
entries, 16 exposed child volumes, independently validated primary/backup GPT
recovery, and primary MBR partitions (extended/logical MBR chains are not yet
exposed). The volume layer is format-neutral and is ready for additional
filesystem and driver backends.
